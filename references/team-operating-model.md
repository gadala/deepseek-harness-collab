# 部门团队 operating model

仅在需要组建、换代或管理 Harness 团队时读取；入口和硬护栏见上级 `SKILL.md`。

## 角色与边界

| 角色 | 责任 |
|---|---|
| Codex 总负责人 | 目标拆分、部门选择、依赖/写权、接口冻结、跨部门集成、独立最终验收、风险升级。|
| 部门主会话 | 一个 headless CLI 进程对应一个部门；理解本部门任务、协调成员、汇总证据、向 Codex 汇报。退出后不视为常驻。|
| 部门成员 | 部门主会话通过真实 `subagent` 创建的直接 child；完成窄工作包并报告，不默认递归委派。|
| Codex 子 agent | 可做独立分析/审查，但不能冒充 Harness 成员；本 Skill 的业务部门证据必须来自真实 Harness CLI。|

部门不另造项目任务板、长期排程或真相账本；既有项目任务板、版本控制和明确写权为权威。一次派发只建立执行登记，完整证据外置。

## 建队与任务卡

只有真实 CLI 接收任务才算建部门。任务卡必须自包含，因为新部门/成员不继承 Codex 或父会话完整历史：

```text
任务ID/部门 | 目标与非目标 | 实际 cwd
允许读集/精确写集/禁止路径 | 当前基线与接口 hash/version
依赖与前置产物 | 验收命令、负例和完成定义
资源/共享输出、超时/有限重试、提交/部署权限 | 证据路径
budgetPolicy=unlimited | 北京时间 gate/跨窗检查点
最多 3 行成员报告或最多 7 行部门报告 | 不得递归委派/越权
```

Codex 保留跨部门写权和交接权；只有明确获得分派权的部门可在父授权范围分割成员写集，并登记 owner。普通成员不得转授权或扩围，新依赖/共享文件/跨部门移交由 Codex 裁定。只读探索可获准有限目录（不含 secret/数据/冻结范围）；新增写路径先补授权。

先冻结接口和写权，再派发；共同依赖由部门先梳理，成员不重复全局探索。父自己要做的写集必须与成员不相交。一次只派有意义、可验收的工作包；小连续动作留在现有主会话。

## 成员生命周期

1. 部门重新判 time gate，确认基线、状态、写权和资源。
2. 用 Harness 原生 `subagent` 创建成员；记录真实 child ID、父 session、任务 ID、写集和回合状态。
3. 同一成员的返修用真实 `send_message` 增量派发，重新给基线/失败/修复范围/验收/变化约束；不能只写“继续上面”。
4. 只在真实 settlement/结果、产物和测试证据齐全后结算；`ready/idle` 不等于销毁（`list_agents` 仅列 continuable，前台后 `(no subagents)` 不表示未委派），`message delivered` 不等于完成。
5. 部门向 Codex 汇总：状态、产物/证据路径、测试、阻塞/未知、下一动作，最多 7 行。成员默认最多 3 行；失败、权限冲突、风险和未知可最少扩展。

当前已核验的是前台 one-shot 和后台 continuable child；跨进程续接、冷恢复、暂停/取消/关闭、同时多成员负载未核验，不能从名称或状态推断存在 `close/wait/resume` API。

## 三次检查与换代

每 3 次有效部门任务（不是工具调用、成员调用、状态读取；同 ID 幂等重试不重复计，启动未知待确认）做一次轻量判断：

- `continue`：当前上下文短、证据清晰、权限仍有效；原部门继续。
- `compact`：先写短交接摘要和证据索引，清理重复叙述，再继续/换新。
- `renew`：上下文污染、阶段切换、权限变化或历史关联成本过高；交接后换新部门。

已接收并真实启动的任务（即使后来失败）才计一次；未启动不计，新 ID 返修正常计数。安全收尾点检查后重置距上次检查计数，保留累计数。每次新 headless 已不累积父会话历史，只整理交接，不为凑三次额外开实例。

需要机器核对交接时使用 [execution-protocol.md](execution-protocol.md) 的 handoff/validate-handoff，保留风险和 unknown；摘要不继承授权。

这不是硬性关闭、预算上限或模型容量阈值。不要为了检查额外调用模型；无变化不汇报。换代必须先确认旧进程及子孙停止、写权/端口/锁/资源释放；unknown 时不能让新部门接管同一写集。新实例核对 HEAD、脏文件、依赖、接口 hash 和权限后再授权；登记新 ID/代次和主 session，新实例不承继旧运行态、隐含授权或 lease。成员完成后无新授权不得主动继续业务，完成/驻留/关闭分开记。

## 质量与冲突

成员自测不能代替 Codex 验收。Codex 需独立查看范围和 diff，运行必要功能负例，核对契约/消费者，最后做实际集成组合回归。保留他人脏改，只回退本批；worker 默认不操作共享 index。发现重复成员、越权写、失联或重复派发时，先冻结受影响写权，登记所有真实 child 和产物，再处理，不能只删报告中的 ID。

外部状态是待核验信息。部门可报告 `blocked/partial/unknown`，不能把接收、投递、空目录、桌面服务连通或“等待对话”写成完成。

## 高效汇报模板

```text
[D-123] done/partial/blocked/unknown；产物：path；证据：hash/log/test。
验证：命令/退出码/关键失败；未验收项：…；下一动作：…。
```

完整日志和 transcript 不塞入父上下文；只给路径、hash、退出码和必要片段。证据丢失、不可读或版本不符标 `unverified`；Codex 验收需真实回读，不能用摘要替代。数据/生产/secret 风险或双 writer 立即停止受影响范围并告警，不因层级等待。无变化不重复报告。
