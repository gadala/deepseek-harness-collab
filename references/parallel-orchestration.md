# 批次、并发与集成

仅在确实需要多部门、多成员或跨部门集成时读取。这里规定登记和收口，不替代 `team-operating-model.md` 的权限规则。

## 批次设计

先由 Codex 画依赖图并选关键路径：接口冻结、共享资源、集成冲突和最终回归留在 Codex；只有互不依赖、写集不相交、可独立验收的包才并行。探索、实现、审查可分阶段；可靠探索已有结论时不重复开一轮。

并发单位包括部门主会话和其原生成员，按全项目 API/429、CPU/GPU、数据库、端口、测试夹具和写锁限制逐步放大。不设人为固定成员上限，也不把 unlimited 当无限并发。争用资源的测试排队；最终组合回归通常串行。

每个批次登记最少：

```text
batch/task ID | department/session | direct child ID（如有）
目标/依赖 | cwd | exact read/write set | baseline + interface hash
start/settlement/exit status | artifact/test evidence | retry/next action
```

登记用于执行证据，不替代既有项目任务板。多 writer/恢复使用 [execution-protocol.md](execution-protocol.md) 的原子 reservation、证据与短交接；控制登记仅由 Codex/获准调度者写。所有真实 child 都登记，不能只留最后一个；父子 usage 可能聚合，不重复计量。

## 派发与收取

部门入口是当次发现的 headless CLI；真实命令和退出码立即保存。部门内部可按下列模式调用原生工具（完整 schema 与已测边界见 `native-subagents.md`）：

```json
{
  "description": "TASK-A1 contract worker",
  "prompt": "自包含任务卡：目标、cwd、精确写集、基线、验收、证据、时间 gate；不得再委派；最多3行报告。",
  "run_in_background": true
}
```

多个成员只有在每个任务、child ID、父 session 和写集均独立时才可启动；当前同时负载未实测，不宣称已验证并发性能。父会话可继续不冲突协调，但不以重复 `list_agents` 忙等。收到真实 settlement 后分别收口。

同一成员返修使用 `send_message`，不为增量修复创建新成员；新成员必须重新完整授权。投递确认不等于答案，settlement 不等于产物通过。

## 真实进程与写权隔离

每部门用一个独立 exec/PTY，保留工具句柄、启动时间、独占脱敏日志和真实退出码；工具句柄、PowerShell job ID、OS PID、部门 ID 与 Harness session/child ID 互不等同。`Start-Job` 的 `Completed` 不证明原生退出码为 0；缺失退出码记 unknown。无输出、lease 超时或 `Transport closed` 不证明未执行/已退出/写权释放。确认本批进程及子孙的命令行、启动时间和 cwd 后才停止或转交，禁止全机 kill。

同工作树仅允许精确不相交写集；大改、不稳定依赖或大量生成物可用获准的隔离 checkout/worktree，但仍须串行集成共享文件。读取别人正在写的文件不是稳定接口，用 hash/受控快照冻结；日志/报告/构建产物也有唯一 writer。

## 重试、失败与幂等

- 启动状态未知：先查真实进程/child/产物，再决定是否补发；不凭空重派。
- 只对确认幂等或未启动的请求有限退避重试；同一缺陷反复出现或硬资源限制时暂停该单元复盘，其他独立任务可继续。
- 同 ID 幂等重试不重复计三次检查；新任务 ID 或新成员必须显式说明原因。
- 认证、时间 gate、写锁、接口变更、资源争用、429、超时分别记录；不要把“失败后换桌面”当默认恢复。
- 任何失败都保留日志、退出码、hash 和最小必要堆栈；不把长日志复制进 Codex 上下文。
- 不因短报告隐藏失败、权限冲突或未知；必要时只扩展影响判断所需的几行。

## 集成收口

0. 变更前记录基线测试和已有失败；交付后冻结只允许验收读，返修重新授权，实施者正常退出与子孙状态需核实。
1. Codex 对每项产物核基线、diff、文件范围、脏修改和写权。
2. 核对接口 hash/version；上游变化后使下游旧 pass 失效并安排定向重验。
3. 用真实输入构造验证（不能只看关键词），运行 worker 自测之外的独立功能负例、契约检查和消费者接线检查。
4. 按既有项目流程串行集成，解决冲突；不 reset/clean 他人改动，不默认替 worker commit。
5. 在最终实际状态上执行组合回归，记录命令、退出码、失败片段和未覆盖项；只有这一步完成后才可报告通过。

`delivered`、`completed`、`passed` 三者分开记。必要测试跑不了时是 `not accepted`，不是成功。功能通过与过程偏差分开记录，局部验收不能称全项目闭环。部署、推送、重启和线上回退需要各自授权；集成回退只回退本批。共享 index 有唯一 integrator，只提交本批精确路径，提交前后查暂存边界，不 `git add .`。

## Token 效率

任务卡只放本包必需资料：稳定约束前置，动态路径/目标末尾；引用版本化文件和证据索引，不复制公共规则。成员先定位符号再读局部，复杂或高风险才展开；部门先做共同依赖扫描，避免多个成员重复全局扫描。日志、测试报告、diff 留文件，父先读命令/退出码/失败片段。

不要每个文件开部门，不为状态检查开模型调用，不高频轮询；无变化不汇报。选择继续、compact 或 renew 以实际上下文和返工风险决定，而不是按固定关闭。用最终验收工作包合计用量/时间/返工/漏检衡量，不虚报“节省百分比”。
